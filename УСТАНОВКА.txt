ШКОЛА HUB — УСТАНОВКА НА SYNOLOGY БЕЗ SSH
=========================================

Редакция архива от 28.10.2026. Все грабли предыдущих попыток обойдены:
порты 5432/8000 наружу не публикуются, пути сборки задаются переменной APP_ROOT
(по умолчанию /volume2/...), тома БД и секретов — новые (старые «битые» не
используются), ключ сессий генерируется сам и хранится в томе secrets_v2.

СОЗДАНИЕ ВЛАДЕЛЬЦА (штатный способ, секретов в файлах нет):
    После ШАГА 3 backend напечатает в журнал ОДНОРАЗОВЫЙ код настройки.
    Container Manager → Контейнер → schoolhub-backend → Журнал — найдите строку
        SchoolHub: требуется первоначальная настройка
        2) Введите код настройки: XXXXXXXX
    Откройте http://<адрес-NAS>:8080, введите этот код и задайте e-mail,
    ФИО и пароль Владельца. Код после использования уничтожается.

АЛЬТЕРНАТИВА (без браузера, полностью автоматически):
    создайте рядом с docker-compose.yml файл .env и укажите в нём
        OWNER_EMAIL=директор@школа.рф
        OWNER_PASSWORD=ВашПарольНеКороче8Символов
        OWNER_NAME=Администратор
        SCHOOL_NAME=МБОУ СОШ №1
    затем повторите ШАГ 3. Файл .env в репозиторий не попадает (покрыт .gitignore).

    Раньше здесь были «учётные данные по умолчанию», зашитые прямо в
    docker-compose.yml. Так делать нельзя: репозиторий публичный, значит пароль
    Владельца был известен всем, а захардкоженный SECRET_KEY позволял подделать
    токен любого пользователя. Подробности — review/REVIEW.md §P0-3.

ШАГ 1. Удалить старое
    Container Manager → Проект → schoolhub → Удалить
    (если спросит «удалить контейнеры» — согласиться).
    Тома удалять НЕ нужно: редакция использует новые имена
    (db_v2, uploads_v2, secrets_v2), старые просто останутся на диске неиспользованными.

ШАГ 2. Заменить файлы проекта
    File Station → /volume2/docker/schoolhub (или /volume1/... — тот том, где
    лежит проект; путь задаёт переменная APP_ROOT в docker-compose.yml) →
    удалите старую папку `app` (в ней только исходники; все данные жили
    в томах, ничего не потеряется).
    Загрузите туда же архив schoolhub-nas-fixed.zip → ПКМ → «Извлечь здесь».
    Должно получиться: /volume2/docker/schoolhub/app, а внутри —
    backend, frontend, docker-compose.yml и этот файл.

ШАГ 3. Собрать проект
    Container Manager → Проект → Создать.
    Имя проекта:  schoolhub
    Путь:         /docker/schoolhub/app
    Файл compose: docker-compose.yml в корне папки (подставится сам).
    Далее → Готово. Первая сборка на ARM-модели занимает 5–12 минут —
    это нормально, прогресс виден в карточке проекта.

ШАГ 4. Войти
    Когда три контейнера (schoolhub-db, schoolhub-backend, schoolhub-frontend)
    станут «Выполняется» и «Исправно», откройте в браузере:
        http://<адрес-NAS>:8080

    Если вы создали файл `.env` с OWNER_EMAIL/OWNER_PASSWORD (см. «АЛЬТЕРНАТИВА»
    выше) — откроется обычная форма входа: войдите этими данными и сразу смените
    пароль (аватар → «Мой профиль»).

    Если `.env` нет — откроется страница ПЕРВОНАЧАЛЬНОЙ НАСТРОЙКИ:
        1) журнал контейнера schoolhub-backend → блок
           «SchoolHub: требуется первоначальная настройка»;
        2) перепишите оттуда код настройки (8 символов);
        3) введите код в браузере, задайте e-mail, ФИО и пароль Владельца.
    Код одноразовый: после создания Владельца он уничтожается.

КАК ПОНЯТЬ, ЧТО ВСЁ ПОШЛО КАК НАДО (журнал schoolhub-backend):
    «Alembic: schema at head …» или «Migrations applied …» — схема базы готова;
    «Starting SchoolHub API (env=prod)»                    — API поднят;
    «Владелец создан из переменных окружения: …»           — сработал .env;
    «SchoolHub: требуется первоначальная настройка»        — .env не задан,
                                                            нужен код (ШАГ 4).
    При повторных стартах ни одного из двух последних сообщений не будет —
    это норма: система уже настроена.

ЕСЛИ ЧТО-ТО НЕ ТАК
    • Порт 8080 занят другим сервисом: в docker-compose.yml у frontend
      замените "${HTTP_PORT:-8080}:80" на "${HTTP_PORT:-8090}:80" и пересоберите.
    • Журналы: Container Manager → Контейнер → нужный → «Журнал»;
      скриншот журнала = половина диагностики.
    • Файл deploy/synology/docker-compose.yml — копия корневого;
      в мастере всегда выбирайте корневой.

ОБНОВЛЕНИЕ В БУДУЩЕМ (тоже без SSH)
    Скачать свежий архив проекта → заменить содержимое папки `app`, СОХРАНИВ:
        • файл `.env`, если вы его создавали (почта/пароль Владельца, порт, LDAP);
        • тома данных — они не в папке `app` и обновлением не затрагиваются
          (БД, загрузки, секретный ключ сессий).
    → Container Manager → Проект → Действие → Пересобрать.
    Правки внутри docker-compose.yml больше не нужны: секретов в нём нет,
    а схему базы backend приводит в актуальное состояние сам при старте
    (журнал: «Alembic: schema at head», «Migrations applied …»).
    Список изменений в версии — docs/CHANGELOG.md.
